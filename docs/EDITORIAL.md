# 《拨弦记》编辑操作手册（Editorial Handbook）

> 一次采集，多次使用。

本手册用于统一《拨弦记》的编辑规范、数据规范、发布流程及版本规划。

适用于：

- GitHub Pages 网站
- 演出情报（attention）
- 弹拨乐一周简报（weekly）
- 微信公众号
- 小红书
- 微信视频号
- RSS
- JSON
- 后续 AI Agent / Codex 自动化流程

---

# 一、项目定位

《拨弦记》（Boxianji）是一个面向中文用户的弹拨乐开放资讯项目。

核心价值不是转载资讯，而是：

> 帮用户减少寻找信息的动作。

所有开发和运营决策遵循：

> 数据负责生长，页面负责呈现。

---

# 二、核心原则

## 一次采集，多次使用

一条演出信息一旦入库，应同时服务于：

- 网站
- 首页
- RSS
- JSON
- 周报
- 后续小程序

禁止重复维护同一份数据。

## 人工审核优先

AI负责：

- 发现
- 整理
- 结构化

人工负责：

- 判断
- 取舍
- 发布

编辑判断始终保留。

## 唯一数据源

所有演出数据以：

`_data/attention.yml`

为唯一事实源。

网站、RSS、JSON、首页及未来周报引用均不得维护独立副本。

## 流程服务于编辑

**流程必须服务于编辑，而不是让编辑服务于流程。**

《拨弦记》的所有数据结构、审核步骤、自动化任务和工具设计，最终目的都是降低编辑的重复劳动，提高信息处理的准确性与效率。

因此：

- 能由 AI 自动完成的重复工作，不要求编辑手动完成。
- 能由数据结构明确解决的问题，不依赖编辑临时记忆。
- 能通过规则提前发现的错误，不留到发布后再处理。
- 不为了流程完整而增加没有实际价值的步骤。
- 当流程与实际编辑工作发生冲突时，优先审视和修改流程，而不是要求编辑迁就流程。
- 新增功能或字段前，应先确认它是否真正降低了编辑成本或提高了数据质量。

**判断一个流程是否合理，不看它有多完整，而看它是否让编辑更轻松、更准确、更可持续。**

> 流程的终点不是流程本身，而是更好的编辑结果。

## 语言规范（Language Style）

《拨弦记》采用中国大陆音乐媒体、专业院团及演出机构的常用表达，避免翻译腔、AI总结式表述和不必要的重复。

### 名称规范

- 吉他类 Festival 优先译作“吉他艺术节”。
- 官方已有固定中文译名时，沿用官方译法。
- 海外城市第一次出现必须带国家，后文可简称。

例如：

- 芬兰坦佩雷
- 西班牙塞维利亚
- 美国布鲁克林
- 罗马尼亚锡比乌

### 用词规范

优先使用：

- 古乐器（不用“历史乐器”）
- 活动期间（不用“节日期间”）
- 举办期间（视语境使用）

避免同一段落重复使用近义词。

例如：

- 吉他艺术节／吉他节：优先使用“吉他艺术节”。
- 活动期间／节日期间：优先使用“活动期间”。

### 外国人名

第一次出现：

> 中文名（Original Name）

后文优先使用中文全名，不重复英文。

例如：

> 阿涅洛·德西代里奥（Aniello Desiderio）

后文：

> 阿涅洛·德西代里奥

### 行文风格

避免：

- 将带来……
- 将举行……
- 呈现出……
- 体现了……
- 强化了……
- 反映出……

优先：

- 直接陈述事实。
- 用具体动作代替抽象总结。
- 让读者自行得出判断。
- 尽量使用自然、准确的中文音乐媒体表达。
- 避免为了制造“总结感”而添加事实之外的判断。

### 编辑原则

- 不为了平衡国内外比例而补充低价值资讯。
- 不为了版面丰满而增加图片或栏目内容。
- 每条资讯应具有独立新闻价值，而非仅作为数量补充。
