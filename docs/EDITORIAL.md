# 《拨弦记》编辑操作手册（Editorial Handbook）

> 一次采集，多次使用。

本手册用于统一《拨弦记》的编辑规范、数据规范、发布流程及版本规划。

适用于：

- GitHub Pages 网站
- 演出情报（attention）
- 弹拨乐一周简报（weekly）
- 微信公众号
- 小红书
- 微信视频号
- RSS
- JSON
- 后续 AI Agent / Codex 自动化流程

---

# 一、项目定位

《拨弦记》（Boxianji）是一个面向中文用户的弹拨乐开放资讯项目。

核心价值不是转载资讯，而是：

> 帮用户减少寻找信息的动作。

所有开发和运营决策遵循：

> 数据负责生长，页面负责呈现。

---

# 二、核心原则

## 一次采集，多次使用

一条演出信息一旦入库，应同时服务于：

- 网站
- 首页
- RSS
- JSON
- 周报
- 后续小程序

禁止重复维护同一份数据。

## 人工审核优先

AI负责：

- 发现
- 整理
- 结构化

人工负责：

- 判断
- 取舍
- 发布

编辑判断始终保留。

## 唯一数据源

所有演出数据以：

`_data/attention.yml`

为唯一数据源。

网站、RSS、JSON、首页及未来周报引用均不得维护独立副本。

## 流程服务于编辑

**流程必须服务于编辑，而不是让编辑服务于流程。**

《拨弦记》的所有数据结构、审核步骤、自动化任务和工具设计，最终目的都是降低编辑的重复劳动，提高信息处理的准确性与效率。

因此：

- 能由 AI 自动完成的重复工作，不要求编辑手动完成。
- 能由数据结构明确解决的问题，不依赖编辑临时记忆。
- 能通过规则提前发现的错误，不留到发布后再处理。
- 不为了流程完整而增加没有实际价值的步骤。
- 当流程与实际编辑工作发生冲突时，优先审视和修改流程，而不是要求编辑迁就流程。
- 新增功能或字段前，应先确认它是否真正降低了编辑成本或提高了数据质量。

**判断一个流程是否合理，不看它有多完整，而看它是否让编辑更轻松、更准确、更可持续。**

> 流程的终点不是流程本身，而是更好的编辑结果。

## 语言规范（Language Style）

《拨弦记》采用中国大陆音乐媒体、专业院团及演出机构的常用表达，避免翻译腔、AI总结式表述和不必要的重复。

### 名称规范

- 吉他类 Festival 优先译作“吉他艺术节”。
- 官方已有固定中文译名时，沿用官方译法。
- 海外城市第一次出现必须带国家，后文可简称。

例如：

- 芬兰坦佩雷
- 西班牙塞维利亚
- 美国布鲁克林
- 罗马尼亚锡比乌

### 用词规范

优先使用：

- 古乐器（不用“历史乐器”）
- 活动期间（不用“节日期间”）
- 举办期间（视语境使用）

避免同一段落重复使用近义词，如：

- 吉他节／吉他艺术节（统一为官方惯用译法）
- 节日期间／活动期间（统一一种表达）

### 外国人名

第一次出现：

> 中文名（Original Name）

后文优先使用中文全名，不重复英文。

例如：

> 阿涅洛·德西代里奥（Aniello Desiderio）

后文写作：

> 阿涅洛·德西代里奥

### 行文风格

避免：

- 将带来……
- 将举行……
- 呈现出……
- 体现了……
- 强化了……
- 反映出……

优先：

- 直接陈述事实。
- 用具体动作代替抽象总结。
- 让读者自行得出判断。

### 编辑原则

- 不为了平衡国内外比例而补充低价值资讯。
- 不为了版面丰满而增加图片或栏目。
- 每条资讯应具有独立新闻价值，而非仅作为数量补充。

# 三、演出数据规范

统一 Schema：

```yaml
id:
date:
city:
title:
performers:
instruments:
link:
```

## 字段说明

| 字段 | 规则 |
|------|------|
| id | 自动生成 |
| date | YYYY-MM-DD |
| city | 中文城市名 |
| title | 官方标题 |
| performers | 中文名数组 |
| instruments | 宽分类数组 |
| link | 公众号链接 |

## 演奏者规范

统一使用中文标准名。

例如：

```yaml
performers:
  - "约兰·索舍尔"
```

英文原名保留在标题需要时出现，不单独存入字段。

## 多位演奏者

使用数组。

```yaml
performers:
  - "王健"
  - "约兰·索舍尔"
```

## 乐器规范

采用宽分类。

| 使用 | 不使用 |
|------|--------|
| 吉他 | 古典吉他 |
| 古筝 | —— |
| 琵琶 | —— |
| 中阮 | —— |

目的：

便于未来筛选、统计及自动化处理。

## 空字段

允许为空。

```yaml
performers: []
instruments: []
```

页面自动隐藏，不删除字段。

# 四、演出入库流程

标准流程：

↓

↓

↓

公众号贴图发布

↓

补公众号链接

↓

attention.yml

## AI 固定输出格式

每次执行“入库”，固定返回：

1. 自动识别结果
2. YAML（可直接复制）
3. 待确认项
4. 入库检查

示例：

```yaml
- id: "20260927-guangzhou-goran-sollscher"
  date: "2026-09-27"
  city: "广州"
  title: "约兰·索舍尔独奏音乐会"
  performers:
    - "约兰·索舍尔"
  instruments:
    - "吉他"
  link: ""
```

公众号发布后，仅补：

```yaml
link: "https://mp.weixin.qq.com/..."
```

## 入库标题规则

《拨弦记》采用“传播标题”与“数据库标题”分层原则。

- **传播标题**：用于公众号、小红书、视频号等平台，可根据平台字数限制进行精简或重写。
- **数据库标题（title）**：必须记录官方完整标题，不因传播需要而缩写。

AI 在入库时按以下优先级识别官方完整标题：

1. 官方正文中的完整标题；
2. 海报上的正式标题；
3. 官方公众号标题；
4. 剧院、乐团或主办方官方公告标题；
5. 若仍无法确认，则标记待确认，不自行猜测。

原则：

> 数据库保留官方事实，传播平台允许编辑表达。

---

## AI 入库校验

每次完成入库后，AI 应主动完成规范校验，并向编辑报告结果。

固定校验项包括：

- `title` 为官方完整标题；
- `performers` 使用中文标准名；
- `instruments` 使用宽分类；
- `date` 为 `YYYY-MM-DD`；
- `id` 唯一且符合命名规范；
- 空字段保留为空数组；
- YAML 可直接复制至 `attention.yml`。

若存在无法确认的信息，应标记“待确认”，不得自行推测。

# 五、周报制作流程

发布时间：

每周六。

制作流程：

Grok

↓

豆包

↓

ChatGPT核验

↓

生成Markdown

↓

发布

## 周报固定结构

1. 编辑导语
2. 近期重要演出（未来14天）
3. 艺术节、赛事与学术动态
4. 乐器制作、非遗与文化动态
5. 音乐会、展会展演与乐团动态
6. 人物资讯
7. 拨弦听曲

## 演出栏目规则

唯一数据源：

`attention.yml`

规则：

- 自动生成未来14天候选演出；
- 按日期排序；
- 编辑精选约3–6场；
- 不复制整个数据库。

原则：

周报是编辑产品，不是数据库。

## 微信公众号

- 常规内容：11:30–12:30 优先。
- 周报：周六中午固定。
- 重大资讯：及时发布。

## 小红书

重点：

- 钩子标题；
- 公域传播；
- 避免明显站外引流。

## 视频号

仅发布：

- 中国巡演；
- 多城巡演；
- 国际大师；
- 大型民族乐团巡演。

不做所有演出同步。

# 十、项目信条

《拨弦记》的长期建设遵循以下原则：

- 数据负责生长，页面负责呈现。
- 一次采集，多次使用。
- AI负责重复劳动，人负责编辑判断。
- 先跑通，再自动化；先验证，再开发。
- 保持极简，不为功能而增加复杂度。


本手册随项目版本持续更新。
